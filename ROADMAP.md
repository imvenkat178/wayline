# Project roadmap

> The long-term goal tree for this project, shared by every human and AI agent working on this repository.
> [HANDOFF.md](HANDOFF.md) records the latest session and the current focus. This file records where the project is going.
> Protocol: [AGENTS.md](AGENTS.md). Commands: `python scripts/roadmap.py next | status | write | check | json`.

## How this file works

**Levels.** A goal (`G1`) is a lasting outcome. A sub-goal (`G1.1`) is a verifiable result inside it. A task (`G1.1.1`) is roughly one session of work.

**Horizon** is set on every sub-goal:

| Tag | Meaning |
| --- | --- |
| `short-term` | Launch 1: needed before real travelers rely on a hosted Boston/MBTA pilot that plans, monitors and exports trips but does not book or take payment |
| `mid-term` | Launch 2 and the first months after Launch 1: contracted flight booking and payments, operational maturity, fuller Boston data |
| `long-term` | Growth beyond the Boston pilot: new regions, calibrated predictions, scale-out architecture, new platforms and business questions |

**Priority** within a horizon: `P0` critical, `P1` high, `P2` normal, `P3` low.

**Status:** `todo`, `doing`, `blocked` (add a `Blocked by:` line), `decision` (add a `Decision needed:` line; only the user decides), `done`, `dropped` (keep the entry and explain why).

**Sub-goal format.** The validator depends on it:

```
### G1.1 Short title
`short-term` `P0` `todo` needs: G2.1
Why: the problem, with evidence.
Evidence: how it was verified, and how strongly.
Done when: the observable result.
- [ ] G1.1.1 A concrete task.
- [x] G1.1.2 A finished task. (done 2026-01-01: the proof, such as a commit, test or file)
```

Optional lines: `From:` names an outside suggestion that was merged in. `Adapted from:` means the suggestion was changed to fit this project, with the reason.

**Rules for every agent**

1. Never renumber or reuse an ID. New entries take the next free number in their parent.
2. Never delete an entry. Set `dropped` and say why.
3. Check a task only with evidence in a `(done YYYY-MM-DD: ...)` note.
4. Update the sub-goal status in the same edit: `doing` when work starts, `done` when every task is checked and the "Done when" result is true.
5. Record newly discovered work here as tasks or sub-goals instead of leaving it in chat.
6. Never move a `decision` sub-goal forward without the user's answer.
7. Before finishing, run `scripts/roadmap.py write`, then `scripts/check_handoff.py --strict`, and log the session in `HANDOFF.md`.
