## Findings that affect the new direction

### N01 Live routing has no fare or flight inventory

**Priority: prerequisite for cheapest-ticket search.** In [routing.mjs](../server/travel/routing.mjs), `OTP_QUERY` requests five transit itineraries without fare fields. `normalizeItinerary()` sets each `priceCents` and `price.totalCents` to null and `bookable` to false. It constrains the live region to the Boston/Massachusetts boundary. The tool definitions and providers contain no flight-shopping adapter. Airport mode accepts a user-entered flight time; it is not flight inventory.

Implement canonical offers, priced local access and an authorized flight/intercity shopping source. Do not promote historical sample prices, the airport helper or the national agency catalog as completed live ticket search.

### N02 Live search controls do not implement full price ranking and constraints

**Priority: before claiming lowest-price results.** The [Planner sort tabs](../src/pages/Planner.tsx) send `priority` back to search. [searchTrips()](../server/domain/tripActions.mjs) passes provider results through; [otpPlan()](../server/travel/routing.mjs) does not apply a local priority sort or budget filter. It applies selected walking/transfer/bus/deadline constraints, not the complete preference model. Five provider-selected itineraries are not an exhaustive cheapest search.

Until pricing exists, make the live price/budget limitations explicit. Then add shared constraint enforcement and a complete-price ranking function with unknowns separated. Validate all priorities, party totals and the original deadline through search and recovery.

### N03 Recovery cost subtracts sunk spending

**Priority: before displaying extra cash or authorizing recovery purchases.** [recoveryCost()](../server/domain/journeys.mjs) computes `alternativeCents - baselineCents - retainedLegCents`. With $100 already paid, no retained legs and an $80 replacement, it returns `incrementalCents: -2000` and `basis: paid`. That is not the $80 needed to buy the replacement; refunds/credits are not established. Existing [economics tests](../tests/recovery-economics.test.mjs) codify the subtraction rather than proving usable recovery cash.

The current [recovery preparation](../server/recovery.mjs) also chooses only the first matching paid ticket. Replace this with ticket-group accounting. Keep immediate purchase cost, applicable credit, pending refund, actual refund and total spend separate. Preserve completed legs and their financial history.

### N04 The AI rewrite still accepts invented named facts

**Priority: before AI makes operational travel claims.** The improved `isSuspectRewrite()` checks numeric sets and presence of negation/uncertainty markers. It does not prove semantic equivalence. A controlled injected model appended “Your airline is Delta Air Lines.” to an unchanged grounded boarding response for a sample ground journey. [runAgentGraph()](../server/domain/agentGraph.mjs) accepted it with mode `Ollama classify · review-mock · composed`.

This was an injected-model reproduction, not an observed live-model incident. The new travel-tool result path exits before free-form composition, which is a useful boundary to retain. The legacy advice path still needs deterministic rendering of operational facts and tests for invented names, reassigned existing numbers and changed meaning. Separately, [external tracing](../server/adapters/tracing.mjs) still wraps full inputs without application-specific redaction; address that before enabling real-user payload traces.

### N05 Setup and operating evidence need completion

**Priority: before a hosted pilot.** [transit setup](../scripts/setup-transit.mjs) downloads Windows Java and invokes `tar.exe`/`java.exe`; provide OS detection or containerized routing before treating setup as portable. [vite.config.ts](../vite.config.ts) proxies to port 4174 while [.env.example](../.env.example) defaults the API to 4173. The revised README explains the required development-port alignment; code defaults still need harmonization.

Real OS push delivery, a configured recovery-email adapter, off-device backup recovery, model factual evaluation and commercial provider access are not cleared by the passing local suite. Retain recorded browser/restore evidence, but run release checks against the intended deployment rather than assuming a prior local process is still online.

### N06 The commerce and recovery model must preserve ticket boundaries

**Priority: before real issuance or rebooking.** Existing sandbox orders and local trip review confirmations are not production supplier transactions. [Trip changes](../server/domain/tripActions.mjs) replace the remaining planning candidate and set `bookingConfirmed: false`; they do not exchange tickets. Generalize recovery around actual position, ticket groups, provider fare conditions, airport procedures and the original arrival constraints. The generic ground transfer buffer must not become an airport connection rule.

Add durable intended operations, provider idempotency, payment/issuance separation, webhook replay handling and reconciliation before enabling paid actions. A saved backup does not reserve a seat or guarantee that the later quote will remain available.

## Reproduction notes

Both probes ran locally without contacting an airline or model provider. The recovery case was:

```js
recoveryCost(
  { price: { totalCents: 10000 }, legs: [] },
  { price: { totalCents: 8000 }, legs: [] },
  10000,
);
// Observed: { incrementalCents: -2000, basis: "paid",
//             retainedLegCents: 0, nonrefundableCents: null }
```

For the model case, construct a sample SF-to-Oakland journey, invoke `runAgentGraph()` for boarding with an injected available provider, return `{"intent":"boarding"}` on the JSON classification call, and return the supplied grounded message plus ` Your airline is Delta Air Lines.` on the compose call. The observed response included the added sentence and the `composed` mode. This demonstrates the remaining boundary without relying on any particular live model to hallucinate.
